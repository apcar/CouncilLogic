# CouncilLogic 0.4.0a1

Alpha prerelease dated November 5, 2026.

CouncilLogic now lets agents request council work while a person controls paid
execution and records the final decision. The seven-provider council, blinded
judging, workload limits, and bounded recovery were already public in 0.3.0a1.
This release adds approval and decision records around that existing workflow.

## What changes for an operator

- **Approve the execution plan before paid work starts.** `council plan`
  reports the question's plan hash, protocol hash, call/output limits, approximate
  input-token projection, and lineage report. `council approve` requires a
  terminal and confirmation of that hash. The single-use token binds the
  question, provider configurations, credential names, protocol, synthesis
  chain, policy, and estimate. A fresh nonce allows the same plan to be approved
  again later. Provider keys are excluded from the record.
- **Give agents a bounded interface.** JSON and MCP interfaces expose plan,
  run, asynchronous start, status, inspect, and list operations. A repeated
  request ID replays the existing run rather than starting a second one.
  Approval and final-decision commands are absent from these interfaces.
- **Record the person's decision.** `council decide` appends accept, reject,
  or defer to a hash-chained ledger. SQLite triggers reject updates and deletes;
  a later decision supersedes the earlier one without erasing it.
- **Choose the provider route.** Keep direct provider keys, or use one
  OpenRouter key with per-seat overrides. Known routed model prefixes must
  match the declared lineage, and equivalent direct/routed identities are
  checked for duplicates. Unknown prefixes are shown as unverified before
  confirmation. Different vendors retain separate model namespaces.
- **Inspect protocol safeguards.** Protocol 1.3.0-beta uses random untrusted-data
  delimiters, reports self-votes, and checks the synthesis outcome against the
  deterministic jury result. A contradiction marks the result degraded.
- **Choose how keys are supplied.** Environment, macOS Keychain, 1Password,
  and a configured secret command are supported. Optional separate-user entry
  points provide an OS boundary for agent access. Key diagnostics redact
  credentials before truncating error messages.

## Try it without credentials

Use a new directory so this exercise does not migrate an existing store:

```bash
council --version
council --mock --data-dir ./work/0.4-proof doctor
council --mock --data-dir ./work/0.4-proof plan --question "Which option should we investigate?" --json
council --mock --data-dir ./work/0.4-proof run --question "Which option should we investigate?" --json
# Substitute the run ID printed above.
council --mock --data-dir ./work/0.4-proof inspect RUN_ID --json
council --mock --data-dir ./work/0.4-proof decide RUN_ID --defer --note "Collect primary evidence before deciding."
council --mock --data-dir ./work/0.4-proof export RUN_ID --output ./work/0.4-proof/report.md
```

Mock execution exercises the record and decision flow. Paid execution requires
the separate [human approval flow](../AGENT-INTERFACE.md#required-flow-for-a-paid-run).

## Upgrade from public main at 8dceb97

Public main identifies its package as 0.3.1a1, database schema as 1, and protocol
as 1.2.2-beta. This release uses package 0.4.0a1, schema 4, and protocol
1.3.0-beta. The HTTP service profile stays at 0.2.0a1.

1. Stop writers and preserve the old executable, configuration, and a consistent
   SQLite backup before opening the data directory with this version. Use the
   SQLite backup API or CLI backup command; copying only the database file can
   omit committed WAL data. Treat backups as private run records.
2. Install the release in a separate environment and check its version. Opening
   an existing store applies the additive schema migrations automatically.
3. Inspect and export existing records. Migration preserves prior runs,
   invocations, and events; it adds decisions, approvals, and agent-request
   tables. It does not invent approval or human decisions for old runs.
4. Start a new run for work that must use the new protocol. Old protocol runs
   remain readable but cannot resume under the new protocol hash, including
   runs that had already completed. Unapproved paid runs are refused by CLI
   resume with exit 4. Protocol-incompatible mock resumes exit 2 before dispatch.
5. Re-plan and obtain a fresh human approval for a new paid run. Tokens from
   earlier local candidates can be invalidated by the expanded plan fingerprint.
6. To revert, stop writers and restore the pre-upgrade backup into a separate
   directory for the old executable. The old executable refuses schema 4;
   an in-place database downgrade is not provided. Keep any new records created
   after migration separately before restoring a backup.

The preparation check creates both completed and pending mock runs using the
actual public-main source, then verifies migration, preservation, inspect/export,
refused legacy resumes, a new decision, a new mock run, database integrity, and
the old executable's refusal of the upgraded database. No provider calls are
needed for this check.

## Boundaries

- This is an alpha. Council output advises; consequential claims still require
  primary-source verification and a person's decision.
- The HTTP service remains mock-only and loopback-only. MCP is a local agent
  interface, not a production network service.
- Same-account agents with unrestricted filesystem or process access are outside
  the approval boundary. Use the documented separate-user setup when OS
  isolation is required; a TTY check alone does not establish a human identity.
- Direct seats trust their configured lineage. Routed prefix checks validate
  configuration, not the backend's actual model identity. Model aliases are not
  independently resolved. OpenRouter receives all routed prompts and introduces
  shared billing, credentials, and availability.
- Logical-call and output limits are not a currency ceiling. Input tokens use a
  character-based approximation. Reasoning limits reduce truncation risk but
  do not guarantee that visible output fits.
- Offline tests and mock demonstrations do not establish current live model
  availability. No new live-provider validation is claimed for this release.

The release tag, wheel, source archive, and checksums identify the same source
revision. Hosted CI is required before publication. The installed operator
wrapper is deployed separately from this public release.
